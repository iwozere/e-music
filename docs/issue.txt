Breaking playback.

  Proposed fix for the root cause

  The pre-buffer reduces freeze frequency but doesn't eliminate the root cause, which is googlevideo CDN throttling datacenter IPs. The permanent fixes, in order of impact:

  1. YouTube cookies (highest impact, zero code). Set YTDLP_COOKIES_FILE to a Netscape-format cookies.txt exported from a browser that is signed in to YouTube. googlevideo serves datacenter IPs at full speed when the request carries valid auth cookies, just like a real browser.
  2. Increase STREAM_PREBUFFER_BYTES if freezes persist after cookies. 512 KB (≈ 32 s) adds only ~0.5 s to startup on a typical connection and eliminates almost all CDN burst gaps.
  3. Add a threaded lookahead queue between ffmpeg stdout and the yield loop (more invasive, medium-term). A bounded queue.Queue lets a background thread drain ffmpeg as fast as it produces data while the yield loop feeds the browser at TCP rate. This decouples ffmpeg throughput
  from HTTP backpressure and gives the browser a larger server-side buffer without holding more RAM than maxsize × 16 KB.
